1. **`ShouldBindBodyWith`**——在一次请求里**多次复用 body** 进行绑定。核心解决的问题是：HTTP 请求的 body 是一次性流，读完就没了，普通 `ShouldBind` 第一次读完后第二次会拿不到数据。
2. 示例
``` go
type formA struct {
	Foo string `json:"foo" xml:"foo" binding:"required"`
}

type formB struct {
	Bar string `json:"bar" xml:"bar" binding:"required"`
}

func main() {
	router := gin.Default()
	router.POST("/bind", func(c *gin.Context) {
		objA := formA{}
		objB := formB{}
		// This reads c.Request.Body and stores the result into the context.
		errA := c.ShouldBindBodyWith(&objA, binding.JSON)
		if errA == nil {
			c.JSON(http.StatusOK, gin.H{
				"message": "matched formA", "foo": objA.Foo
				})
			return
		}
		// At this time, it reuses body stored in the context.
		errB := c.ShouldBindBodyWith(&objB, binding.JSON)
		if errB == nil {
			c.JSON(http.StatusOK, gin.H{
				"message": "matched formB", "bar": objB.Bar
				})
			return
		}
		c.JSON(http.StatusBadRequest, gin.H{
			"error": "request body did not match any known format"
			})
		})
		
	router.Run(":8080")
}
```
3. 注意事项
	1. **body 有大小限制**：`ShouldBindBodyWith` 把整个 body 读进内存存 context，超大 body 会占内存。Gin 默认 `MaxMemory` 限制 multipart，但 JSON 不限，生产环境要自己加 `http.MaxBytesReader`
	2. **只能复用同类型 binder 的 body**：第一次用 `binding.JSON` 存的是原始 bytes，第二次用 `binding.JSON` 或 `binding.XML` 都能从 bytes 重新解析；但不能混用流式 binder
	3. **性能开销**：多次解析同一份 body 有 CPU 成本，能确定格式时优先用单次绑定
	4. **典型场景**：接入第三方 webhook 时，同一个端点可能收到不同格式的请求（如兼容旧版 API），需要"试错式"绑定
