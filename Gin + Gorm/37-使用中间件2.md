1. `gin.New() vs gin.Default()`
``` go
// gin.New() 创建一个不带任何中间件的空白路由器
// gin.Default() 是 gin.New() + gin.Logger() + gin.Recovery() 的便捷封装，两者等价
r := gin.New()  
r.Use(gin.Logger())  
r.Use(gin.Recovery())
//等价于
r := gin.Default()
```
2. 全局中间件：在路由创建时就传入 middleware，就如上面的 r 创建。
3. 分组中间件
``` go
g1 := r.Group("/admin")  

// middleware只在访问 /admin/* 才会生效
g1.Use(func(c *gin.Context) {  
    token := c.Query("token")  
    fmt.Printf("token: %v\n", token)  
    if token == "valid" {  
       c.JSON(200, gin.H{  
          "access": "登陆成功",  
       })  
       return  
    }  
    // Go 的 return 只结束当前函数，对 Gin 中间件来说，它只结束中间件函数本身，不会阻止后续中间件或最终 handler 继续执行，要用 Abort() 才能跳过 handler 执行
    c.AbortWithStatusJSON(401, gin.H{"error": "登陆失败"}) 
    // c.AbortWithStatusJSON 等价于下面这三步：
	// c.String(401, "登陆失败")  
	// c.Abort()    
	// return
})  

g1.GET("/dashboard", func(c *gin.Context) {  
    c.String(200, "访问服务")  
})
```
4. **注意：** 执行 `c.Abort( )` 之后后续的**中间件** 和 **handler** 都不会再被调用。
5. 路由级中间件
``` go
// 一个路由可以挂多个中间件,按顺序执行 
// r.GET("/path", 中间件1, 中间件2, ..., 最终handler)
// 中间件和 handler 在参数位置上是 同等对待 的，都是 gin.HandlerFunc 类型。Gin 把最后一个参数当作 handler，前面的都按中间件顺序执行。
r.GET("/route-mw", Authorized(), TimeStamp())
```
