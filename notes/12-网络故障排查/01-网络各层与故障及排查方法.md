1. **物理层**：光纤、网线、WiFi 信号
	1. 故障特征
		1. 网卡灯不亮
		2. WiFi 连不上
		3. 光猫"光信号"灯变红
		4. 网线被踢松了
		5. 水晶头坏了
		6. 光纤被老鼠咬了
	2. 排查方向
		1. 看设备指示灯
		2. 换网线/换端口/换设备交叉验证
		3. `ping 127.0.0.1`（不通说明是本机协议栈或网卡驱动问题）
2. **数据链路层**：保证 物理层 要带给 网络层 的内容可以安全到达
	1. 故障特征
		1. 连上 WiFi 却拿不到 IP（看到 `169.254.x.x` 这种自动私有地址）
		2. 同一局域网内互相 ping 不通
		3. ARP 异常、MAC 冲突
	2. 排查方向
		1. `ipconfig /all` 看 DHCP 是否成功
		2. `arp -a` 看 ARP 表
		3. `getmac` 看网卡地址
		4. 重启路由器常能解决 DHCP 故障
3. 网络层：负责线路应该怎么走（比如发送给哪台机器，通过ip找到机器），比如收到dns解析的ip后，如果ip不在局域网，就发给网关处理。
	1. 作用
		1. 分配 IP地址
		2. 规划路线 -> 路由选择，决定下一步该往哪走
		3. 把数据打包成 “包裹”
	2. 故障特征
		1. 局域网内正常，但出不了网关
		2. 能 ping 通 IP 但换个网段就不行
		3. 路由/网关配置错了
	3. 排查方向
		1. 接力 ping：`ping 网关` → `ping 8.8.8.8`；`tracert` 看断在第几跳；`route print` 查路由表；检查 IP、掩码、网关
4. 传输层：负责**把数据准确交给机器上的某个程序（端口），并且可以选择要不要保证可靠性（TCP/UDP）**。
	1. 传输协议
		1. TCP
			1. 可靠、有序、不丢
			2. 用在 网页、文件下载、邮件
			3. 先建立连接（三次握手）才能使用
		2. UDP
			1. 快，不保证送到
			2. 视频直播、游戏、DNS
			3. 无连接、直接发
	2. 传输层的地址是 **IP + 端口**，这叫**套接字（Socket）**。
	3. 故障特征
		1. 页面转圈直到超时（连接建不起来）
		2. `连接被拒绝`
		3. 视频卡顿丢包
		4. 防火墙把端口拦了
		5. 排查方向
			1. `Test-NetConnection host -Port 443` 或 `telnet` 试端口
			2. `netstat -ano` 看本机监听端口
			3. Wireshark 抓包看 SYN/SYN-ACK 有没有回
			4. ping 看丢包率和延迟
